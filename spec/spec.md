## 1. 项目背景与目标

用户已有完整的减脂餐计划与运动计划（由 AI 生成，见 `减脂餐.md` / `运动计划.md` 样例），但执行中存在两个痛点：

1. **忘记执行**：到了饭点/训练时间想不起来该吃什么、该练什么；
2. **加餐失控**：额外吃了外卖/KFC 后，不知道当天热量缺口还剩多少。

**产品目标**：做一个安装在安卓手机上的单机 App（uni-app 开发），只做三件事——**导入计划、到点提醒、打卡**，外加**热量缺口计算**。界面简洁，离线优先，无账号无云端。

**明确不做**（控制范围）：
- 不内置自有 AI 服务（所有 AI 能力——计划文档转 JSON、食物热量查询——均通过用户自配的 API Key 实现）
- 不做账号系统、云端同步、社交功能
- 不做 iOS（v1 只打安卓包）
- 不做复杂的饮食/运动数据库管理（内置一份常见食物热量表即可）
- 不在现有页面内新增轻引导/提示卡/文案改动——引导能力只存在于引导页与使用指引页（F7/F8 范围硬约束）

## 2. 用户与使用场景

单一用户（本人），单机使用。

| 场景 | 描述 | 涉及功能 |
|------|------|----------|
| S1 首次导入 | 找 AI 生成计划 JSON → 复制 → App 内粘贴导入 → 预览确认 | 计划导入、模板 |
| S2 日常执行 | 12:00 收到通知「该吃午餐：冻豆腐虾仁荞麦面」→ 打开 App → 打卡 | 提醒、打卡 |
| S3 傍晚训练 | 18:30 收到通知「适应期·快走训练」→ 完成后打卡 | 提醒、打卡 |
| S4 下午加餐 | 16:00 提醒加餐 → 吃了水煮蛋 → 打卡（计划内，100 kcal） | 提醒、打卡 |
| S5 自由餐热量 | 周六吃了 KFC 套餐 → App 搜「香辣鸡腿堡套餐」→ 记录 1100 kcal → 查看当天缺口 | 食物库、加餐、缺口 |
| S6 外卖热量 | 点了份黄焖鸡外卖，库里搜不到 → AI 联网查询热量 → 确认记录 | AI 查询、加餐 |
| S7 复盘 | 周日查看本周打卡情况和每天热量缺口 | 统计 |
| S8 换计划 | 计划到期/不满意 → 重新找 AI 生成 → 再次导入覆盖 | 计划导入 |
| S9 首次使用 | 新装打开 App → 引导填基础信息算出每日基础消耗 → 录入饮食计划（逐条 / 整日一句话）→ AI 生成 → 编辑确认 → 进入正常使用 | 首次使用引导（F7） |
| S10 想学功能 | 加餐/加练/提醒收不到/统计不会看 → 设置 → 使用指引 → 图文教程（真实截图）随时回看 | 使用指引（F8） |

## 3. 功能需求

优先级说明：P0 = v1.0 必须完成；P1 = 后续版本可选增强。

### F1 计划导入（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR1.1 | 粘贴 JSON 导入 | 输入框粘贴 JSON → 解析校验 → 预览 → 确认后生效 |
| FR1.2 | 文件导入 | 可选择手机本地 `.json` 文件导入（同等校验流程） |
| FR1.3 | 格式校验 | 按 [import-format.md](import-format.md) 第 5 节规则校验，错误信息为中文并定位到具体条目/字段 |
| FR1.4 | 导入预览 | 确认前显示：计划名、时间段、餐食 N 项、运动 M 项、每日目标热量 |
| FR1.5 | 增量导入 | JSON 含 `meals` 则增量合并餐食计划、含 `exercises` 则增量合并运动计划（相同 id 更新该项，新 id 追加到列表末尾，另一模块不受影响）；`meta` 中的 tdee/dailyCalorieTarget 写入设置 |
| FR1.6 | 导入后即时生效 | 今日页立即按新计划渲染；当日未过期的提醒立即重新调度 |
| FR1.7 | 内置模板 | 模板页展示 JSON 格式说明 + 完整示例（template.json）+ AI 提示词，均可一键复制 |
| FR1.8 | AI 智能导入（主推） | 粘贴计划文档（Markdown/纯文本/聊天记录）→ 调用用户自配 AI 转 JSON → 校验 → 预览 → 导入；未配置 Key 时弹出 AI 配置弹层（页内填 Key，保存后立即继续原操作） |
| FR1.9 | 入口整合 | 导入页双模式切换：「✨ AI 生成（默认）」+「手动 JSON」（粘贴/文件/格式说明/模板合并入口）；计划页主按钮直达 AI 导入 |

### F2 到点提醒（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR2.1 | 本地通知 | 按计划项的 `time` 发系统通知：标题区分「用餐提醒/运动提醒」，内容含名称与简短备注 |
| FR2.2 | 提前量 | 全局可设提前 0/5/10/15/30 分钟提醒，默认 0 |
| FR2.3 | 开关 | 全局总开关；单个计划项可关闭（`reminder:false` 或详情页切换） |
| FR2.4 | 离 App 生效 | App 退到后台或被杀进程后，当天已调度的提醒仍能到达 |
| FR2.5 | 点击跳转 | 点击通知打开 App 并定位到今日页对应计划项 |
| FR2.6 | 调度时机 | App 启动/回到前台、导入成功、修改提醒设置后，自动重算今日+明日提醒 |
| FR2.7 | 省电引导 | 设置页提供国产 ROM 自启动/电池白名单的图文引导（不保证全自动跳转） |

已知限制（如实告知用户，见 design.md 第 8 节）：手机重启后需打开一次 App 恢复调度；部分 ROM 极端省电策略可能拦截，需加白名单。

### F3 打卡（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR3.1 | 逐项打卡 | 今日页每个餐食/运动项有打卡按钮，点击即记录（含时间戳） |
| FR3.2 | 取消打卡 | 当日内可再次点击取消；历史日期只读不可改 |
| FR3.3 | 打卡状态可视化 | 已打卡项有明显视觉反馈（对勾+变色）；今日页显示完成进度（如 3/5） |
| FR3.4 | 连续打卡 | 统计页显示连续完成天数（当日计划项全部打卡才算一天完成；今日加餐不参与完成度） |
| FR3.5 | 打卡持久化 | 数据本地持久化，卸载重装前不丢失（重装丢失可接受，v1 无导出） |
| FR3.6 | 当日实际热量 | 每餐可 ✎ 调整「今日实际摄入」（覆盖计划值，含备注），仅当天生效，明天自动恢复计划值；打卡后按实际值计入缺口 |
| FR3.7 | 实际热量 AI 估算 | 调整弹窗内大白话描述（如"没买到豆浆只吃了包子"）→ AI 估算总热量并展示拆解，确认后填入 |

### F4 加餐与热量缺口（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR4.1 | 今日加餐（唯一计划外入口） | 加餐页三方式录入：内置食物库搜索 / AI 估算 / 手动；**添加即计入缺口**（无需打卡），仅当天有效，明天自动消失，不影响整体计划与完成度 |
| FR4.2 | 内置食物库 | 离线搜索常见食物：KFC 单品/套餐、麦当劳、常见外卖（黄焖鸡/麻辣烫/炒饭/螺蛳粉等）、饮品零食，约 70 条种子数据 |
| FR4.3 | AI 联网查询 | 库里搜不到时，调用用户自配的 AI API（OpenAI 兼容协议，DeepSeek 默认）查询食物热量，返回结构化结果供确认（热量可编辑） |
| FR4.4 | 加餐管理 | 今日加餐列表（今日页 + 加餐页）可删除单条，热量从缺口中扣回；来源标记（食物库/AI/手动） |
| FR4.5 | 缺口计算 | 今日页实时显示：目标摄入 / 已摄入（已打卡餐实际值+今日加餐）/ 运动消耗 / **热量缺口**；缺口 = (TDEE + 运动消耗) − 已摄入 |
| FR4.6 | 缺口着色 | 缺口 < 0 红色（超标）；0-300 橙色；300-800 绿色（推荐区间）；> 1000 橙色（过猛提示） |
| FR4.7 | 自由餐补录 | `calories:null` 的计划项打卡后，提示「去记录实际热量」（✎ 调整或 AI 估算） |

| FR7.5 | 保存口径 | 「保存并继续」经现有 `settings.update()` 写入 tdee（=基础消耗）/ bmr / dailyCalorieTarget，与设置页同路径同口径；基础信息存 `onboardingState.profile`（settings 不加字段） |
| FR7.6 | 推荐目标摄入 | 默认 = 参考总消耗 − 400 kcal（约每周减 0.4kg），下限保护：女 1200 / 男 1500，可手改 |
| FR7.7 | 计划录入双模式 | 「✍️ 逐条录入」（餐类/名称/时间/星期/热量，含运动条目，星期默认每天可 chips 多选）与「📝 整日一句话」（一次性录入当天全部餐食+运动）可切换，草稿在模式间保留 |
| FR7.8 | AI 创造计划 | 输入内容 → AI 生成结构化计划（拆分餐次/配建议时间/估算热量/运动估消耗），输出字段与 [import-format.md](import-format.md) 一致，经 `normalizePlan` 校验并自动补默认（id/reminder 等）；失败自动重试 1 次 → 中文错误 + 重试/转手动双按钮，输入文本保留 |
| FR7.9 | AI Key 配置 | 未配置时引导页内弹精简配置层（服务商预设/Key/测试连接，调用现有 `switchProvider`/`updateAI`/`testAI`，不改设置页）；可「暂不，手动模式」跳过，纯手动模式（手填热量/自由餐）永远兜底 |
| FR7.10 | 确认前编辑与 AI 重估 | 每条可编辑（名称/时间/星期/热量或时长/餐类）、可删（toast 撤销 5 秒内有效）、可追加；改动条目标 dirty，可单条或全部 AI 重估：餐食复用 `queryCalorie`、运动复用 `estimateBurn`（带体重），并发 ≤2，失败保留原值并提示 |
| FR7.11 | 确认前汇总条 | 本地实时计算：摄入 Σ（自由餐不计）/ 消耗 Σ / 预计缺口（=基础消耗+运动Σ−摄入Σ），按 FR4.6 阈值着色 |
| FR7.12 | 确认生效 | 「确认完成，开始用」经现有 `importPlan()` 增量合并写入 + 当日/次日提醒立即调度 + done 置位 + 回今日页 |
| FR7.13 | 只增不改约束 | 对现有文件的触碰仅限：① `pages.json` 注册 2 个新路由；② `index.vue` onShow 首启判断约 5 行；③ `settings.vue` 新增「帮助」分组入口；④ `utils/ai.js` 文件末尾追加 `generatePlanFromInput`（现有函数零改动）。其余全部为新增文件 |

| FR9.1 | 导出备份 | 设置页「导出历史数据备份」→ 二次确认（说明导出内容 + 提示含 AI API Key 需妥善保管）→ 生成 `zhiqing-backup-YYYYMMDD-HHmmss.txt` 写入系统 Download 目录（内容为 JSON 文本；文件名全 ASCII，zhiqing 为「知轻」拼音，防中文名在传输端截断/乱码）→ 成功弹窗展示文件路径 + 「分享文件」按钮（调系统分享） |
| FR9.2 | 导出数据范围 | 全量快照 8 项：planData（含 meta.startedAt）、checkRecords、mealAdjust、tempTasks、extraFoods、settings（含 AI 配置）、onboardingState、apiUsage；顶层含 `app:'jianfeidazi'`/`type:'backup'`/`formatVersion:1`/`exportedAt` 标识 |
| FR9.3 | 导入与文件读取 | 设置页「导入历史数据备份」→ 系统文件选择器（App 端 `pickBackupFile` 走 SAF/ACTION_OPEN_DOCUMENT，setType('*/*') 全量展示 dat/txt/json）→ 按纯文本读取（`readBackupFile` 兼容本地路径 / file:// / content://；当前导出格式为 .txt，旧版 .dat 备份内容同为 JSON 文本，扩展名与读取无关，按纯文本读取即可兼容）→ JSON 解析 + 结构校验（app/type/formatVersion/data）→ 失败中文报错且本机数据不变 |
| FR9.4 | 导入概要展示 | 校验通过后弹层展示备份概要（导出时间、餐食/运动条数、打卡天数与条数、临时任务条数、是否含 AI Key），再选导入方式（增量 / 覆盖 / 取消） |
| FR9.5 | 增量导入 | 合并计划（复用 importPlan：同 id 更新、新 id 追加、另一模块不受影响；startedAt 保留本机值，为空才回填）；打卡按 checkedAt 取较新（不把已打卡倒回未打卡）；mealAdjust/tempTasks/extraFoods 按 id 合并（导入优先）；**不覆盖** settings/onboardingState/apiUsage；确认弹窗必须提示「可能导致历史日期热量统计变化（计划项热量被备份覆盖），建议将不同版本数据分别导出备份」；完成后当日/次日提醒重新调度 |
| FR9.6 | 覆盖导入 | 强确认（「清空并替换本机全部数据，当前数据不可恢复，建议先导出备份」+「备份含 AI API Key 将一并恢复，请确认来源可信」）→ 全量替换 8 项（settings 用默认值深度合并补缺）→ 提醒重新调度 → toast 导入成功 |

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 简洁性 | 底部 4 个 Tab（今日/计划/统计/设置）；今日页打开即见当日任务，两次点击内完成一次打卡 |
| 离线优先 | 除 AI 查询外全部功能离线可用；未配置 AI 时食物库+手动录入兜底 |
| 性能 | 冷启动 ≤ 2s；页面切换无明显卡顿；本地存储单键数据量控制在几百 KB 内 |
| 兼容 | Android 8.0+，重点适配 10-14；覆盖小米/华为/OPPO 等主流 ROM 的通知与省电策略 |
| 隐私 | 无自有服务器、无数据上传；AI 查询仅把食物名称发给用户自配的 API |
| 语言 | 简体中文界面 |
